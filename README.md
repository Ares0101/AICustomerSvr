# 多 Agent 智能客服系统 Demo（含 Guardrails 安全控制）

本项目是一个**可运行的 Multi-Agent 智能客服系统 Demo**，用于演示如何使用 OpenAI + Agents SDK 构建一个真实企业场景的「智能客服系统」，并通过 Guardrails（安全护栏）实现合规控制。
由于openai新账号不再给免费使用额度，改用国内deepseek大模型，当然也可以根据需要选用别的大模型
该 Demo 重点展示：

- 多 Agent 自动路由（订单 / 退款 / 投诉）
- Triage（意图识别 + 分发）
- 输入 Guardrail（禁止回答敏感问题）
- 输出 Guardrail（防止模型输出违规内容）
- 支持异步调用（AsyncOpenAI）
- 可扩展为企业级客服中台架构

## 项目功能说明

### 1. 多 Agent 智能分流

系统会自动识别用户意图，并将问题分配给对应的业务 Agent：

| 用户问题类型 | 对应 Agent |
|------------|------------|
| 查询订单状态、物流、发货 | `OrderAgent` |
| 退款、退货、取消订单 | `RefundAgent` |
| 投诉、差评、升级人工 | `ComplaintAgent` |
| 无法识别的问题 | `FallbackAgent` |

例如：

- 用户问：**“订单到哪了？”** → 自动分发给 `OrderAgent`
- 用户问：**“我要退款”** → 自动分发给 `RefundAgent`
- 用户问：**“我要投诉你们客服”** → 自动分发给 `ComplaintAgent`

---

### 2. Guardrails 安全护栏控制

系统内置安全策略（Guardrails），用于限制模型回答某些高风险内容。

**禁止回答的内容包括：**

- 🚫 法律咨询类问题
- 🚫 医疗诊断 / 治疗建议
- 🚫 政治敏感内容

Guardrails 分为两层：

- **输入 Guardrail**：用户提问一旦涉及敏感领域，直接拒绝处理
- **输出 Guardrail**：即使模型生成了违规内容，也会被拦截替换为安全回复

---

### 3. 企业级客服工作流模拟

本 Demo 设计为真实客服系统架构风格，具备典型业务逻辑：

- 订单号识别
- 退款政策解释
- 投诉升级与工单生成（模拟）
- 输出统一格式（客服语气）
